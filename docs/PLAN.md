# UCSC Schedule → Google Calendar — plan

A Chrome MV3 extension that reads a UCSC student's enrolled schedule and writes it
straight into Google Calendar as recurring weekly events, one click.

## Decisions (locked)

| Topic | Decision |
|---|---|
| Calendar target | **Google Calendar** one-click via the API, **and** a **.ics download** (Apple Calendar, or import into Google yourself). |
| Export trigger | Google: one click → OAuth → events created directly. ICS: one click → file download, no sign-in. |
| Sources | **MyScheduler** (`ucsc.collegescheduler.com`) first; **MyUCSC portal** (`my.ucsc.edu`) later. |
| Recurring events | One `RRULE:FREQ=WEEKLY;BYDAY=…;UNTIL=<lastInstruction>` per meeting pattern. Lecture and lab = separate series. |
| Timezone | `America/Los_Angeles` with a real VTIMEZONE / `start.timeZone` (fall crosses the DST change). |
| Holidays | `EXDATE` for each campus holiday landing on a meeting day. From the bundled academic-calendar dataset. |
| Week before finals | Normal instruction — covered by the RRULE, no special case. |
| Finals week | Separate one-off event per class, computed from the registrar's final-exam matrix: `(day-group, class start time) → (exam date, exam time)`. |
| Unmatched finals | If a class's start time matches no matrix row (non-standard / online / odd time): **create nothing, list it** in the popup for the user to add manually. |
| Async / online-no-time courses | **Ignored entirely.** A class is exported only if it has ≥1 meeting with real days + times. Synchronous online (has meeting times, location "Online") **is** included. |
| Location | Building/room in `LOCATION`; instructor + location + class # + section + status in `DESCRIPTION`. |
| Reminder | User picks lead-time minutes in the popup (presets none/10/15/30/60 + custom) → `reminders.overrides`. |
| Target calendar | Popup dropdown: user's existing calendars + "Create new calendar…". |
| Distribution | Public Chrome Web Store → needs privacy policy, permission justifications, and Google OAuth verification for the calendar scope (start early). |
| Re-export | Deterministic `iCalUID` per `term + classNumber + meetingIndex` (and `+ "final"`) so re-running updates instead of duplicating. Store inserted IDs for "undo last export". |

## Data model (parser output)

```
ScheduleData {
  ok, source, term { label:"Fall 2026", raw, year, quarter },
  classes: [ {
    classNumber, subject, course, section, title, status, credits,
    component: "LEC" | "LAB" | "DISC" | "SEC",
    online: bool,                       // true only when async/no-time
    meetings: [ { days:["Mo","We","Fr"], start:"16:00", end:"17:05", location } ]
  } ]
}
```

Everything downstream consumes only this. Parsers are the only source-specific code.

## Bundled datasets — `src/lib/datasets/`

Generated by `npm run build:data` from `data/raw/`:

- `academic-calendar.json` — per term: `instructionStart`, `instructionEnd`,
  `finalsStart`, `finalsEnd`, `holidays[]`, `timezone`. Hand-transcribed from
  `Academic-Calendar-2026-27.pdf` (few dates each; update yearly).
- `final-exam-matrix.json` — per term: `examWindow`, `rows[{dayGroup,startTime,examDate,examStart,examEnd}]`,
  `nonStandard{1,2}`. Parsed from the registrar CSV.

## Phases

- **P0 — scaffold + parser.** ✅ MyScheduler parser + fixture test, datasets build,
  popup that lists detected sections.
- **P1 — Google export.** ✅ `getAuthToken` OAuth (Chrome-extension client), writable-
  calendar picker, reminder-minutes UI, recurrence builder (RRULE + holiday
  EXDATEs), sequential `events.insert` in the service worker, deterministic
  `iCalUID` + stored event IDs for re-export/undo.
- **P2 — finals + create-calendar.** ✅ `resolve-final.mjs` matches lectures to
  the exam matrix by day-family + start time; one-off exam events; unmatched
  lectures surface as an "add manually" list. Per-section checkboxes in the
  popup. "＋ New calendar" option (adds `calendar.app.created` scope; undo of a
  new-calendar export deletes the whole calendar).
- **P3 — MyUCSC portal.** ✅ `myucsc-parse.mjs` reads the PeopleSoft "Class
  Schedule" grid (keyed off `PAGROUPDIVIDER` + `<th>` labels, not `win0div*`
  ids). Adds instructor + full component names; per-section `startDate`/`endDate`
  override the dataset instruction window in `buildEvents`. Content script runs
  in all frames; only the schedule frame answers. Popup works on both hosts.
- **P4 — .ics download.** ✅ `ics.mjs` serializes `buildEvents` output to RFC 5545
  (static `America/Los_Angeles` VTIMEZONE, line folding, text escaping, `VALARM`
  from the reminder, stable `UID`s). Popup gains a "Download .ics" button that
  works without connecting Google; the Google one-click sits below it.
- **P5 — release.** Per-course colors, options page, real icon, privacy policy
  page, Google OAuth verification, Chrome Web Store submission (extension ID
  changes on publish → update the OAuth client's item ID).

## Known edge cases / assumptions

- MyScheduler exposes no instructor — blank until MyUCSC (P3) or the grid view.
- Component inference is heuristic (title "Lab" → LAB; trailing section letter or
  0 credits → SEC; else LEC). Only LEC gets a computed final.
- Multiple meeting patterns per class are supported (parsed from repeated
  `sr-only` spans), deduped.
- Emotion CSS class hashes on MyScheduler are unstable — selectors key off table
  headers, `caption`, and `aria-label`, never `css-*` hashes.
- Take-home / no finals / instructor-rescheduled exams exist — computed exam
  events carry a "confirm with your instructor; room may differ" note.
